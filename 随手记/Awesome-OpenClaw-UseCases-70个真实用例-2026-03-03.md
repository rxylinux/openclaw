#### 三层内存系统 (#04) ⭐ 重点推荐

**Introduction**:
结构化的代理内存方法，平衡速度和持久性。使用三层：
- 长期核心原则（很少改变）
- 日常事件日志（临时工作内存）
- 项目特定追踪（目标、阻塞、下一步）

**Why it matters**: 没有结构化内存的代理会在会话之间丢失上下文。这个系统确保重要信息持久化，同时避免 token 膨胀。

**真实示例**: 代理在 MEMORY.md 中跟踪核心价值观，在 2026-02-19.md 中跟踪日常决策，在 PROJECTS.md 中跟踪活跃项目状态及明确的下一步行动。

**目录结构**:
```
workspace/
├── MEMORY.md              # 长期：原则、锚点、目标
├── PROJECTS.md            # 项目：状态、阻塞、下一步
└── memory/
    ├── 2026-02-19.md      # 日常：事件、决策、上下文
    ├── 2026-02-18.md
    └── heartbeat-state.json
```

**迁移规则**:
| 来源 | 目标 | 时机 | 示例 |
|------|------|------|------|
| 日常日志 | MEMORY.md | 原则确认 | "用户偏好直接风格" |
| 日常日志 | PROJECTS.md | 任务变成项目 | "构建用例" |
| PROJECTS.md | MEMORY.md | 项目完成 | 经验教训 |
| 旧日志 | 归档 | > 30 天 | 压缩为月度 |

### 安全监控 (10)

**特点**: 审计和漏洞检测

#### SSH 密钥扫描器 (#09) ⭐ 重点推荐

**Introduction**:
安全审计工具，扫描文件系统中暴露的 SSH 私钥和 AWS 凭证。识别不安全密钥（错误权限、错误位置），检查 git 仓库中的密钥，并对潜在的凭证泄露发出警报。

**Why it matters**: SSH 密钥经常被复制到错误位置、提交到 git 或留下不安全的权限。自动化扫描在攻击者之前捕获这些问题。

**真实示例**: 代理扫描 ~/.ssh、~/Downloads、项目目录，发现 3 个权限为 644 的密钥和 1 个明文 AWS 密钥，生成包含修复步骤的安全报告。

**扫描配置** (`config/security-scan.json`):
```json
{
  "scan_paths": [
    "~/.ssh",
    "~/Downloads",
    "~/projects",
    "~/workspace"
  ],
  "exclusions": [
    "node_modules",
    ".git/objects",
    "*.pub"
  ],
  "patterns": {
    "ssh_key": [
      "BEGIN OPENSSH PRIVATE KEY",
      "BEGIN RSA PRIVATE KEY",
      "BEGIN EC PRIVATE KEY"
    ],
    "aws_key": [
      "AKIA[0-9A-Z]{16}",
      "aws_access_key_id",
      "aws_secret_access_key"
    ]
  }
}
```

**检查项目**:
- SSH 密钥的文件权限（必须是 600）
- 密钥是否在 git 仓库中
- 密钥是否在非标准位置
- AWS 凭证是否以明文存储

**安全报告格式**:
```markdown
🔒 SSH Key Security Scan - 2026-02-19

## Summary
- SSH keys found: 5
- With issues: 3
- AWS credentials: 1
- Overall risk: MEDIUM

## SSH Keys

### ✅ /home/user/.ssh/id_rsa
- Permissions: 600 ✓
- Location: Standard ✓
- In git: No ✓

### ⚠️ /home/user/Downloads/aws-key.pem
- Permissions: 644 (FIX: chmod 600)
- Location: Non-standard (FIX: mv to ~/.ssh/)
- In git: No

### 🚨 /home/user/projects/old-repo/deploy_key
- Permissions: 644
- Location: In git repository!
- Risk: HIGH - May be committed

## Actions Required
1. [ ] chmod 600 ~/Downloads/aws-key.pem
2. [ ] mv ~/Downloads/aws-key.pem ~/.ssh/
3. [ ] Check if deploy_key is committed: git log --all -- deploy_key
4. [ ] Rotate AWS keys if credentials file was exposed
```

**修复脚本**:
```bash
# Fix permissions
chmod 600 ~/.ssh/*

# Remove from git if accidentally committed
git rm --cached deploy_key
echo "deploy_key" >> .gitignore

# Move to correct location
mv ~/Downloads/*.pem ~/.ssh/

# Rotate AWS keys
aws iam update-access-key --access-key-id AKIA... --status Inactive
aws iam create-access-key
```

**成功指标**:
- [ ] 100% 的 SSH 密钥权限为 600
- [ ] 零个密钥在 git 仓库中
- [ ] 所有密钥在 ~/.ssh 目录中
- [ ] AWS 凭证已加密
